# Avl301 Protocol Documentation

## Overview

The Avl301 protocol is a binary protocol used by various GPS tracking devices for transmitting location and status information. This protocol supports device identification, position reporting, and status updates through a compact binary format.

## Protocol Specifications

### Connection Type

- **Transport Protocol**: TCP
- **Default Port**: Varies by device configuration

### Message Format

All messages in the Avl301 protocol follow this general structure:

```
[Header Byte] [Message Type] [Length] [Payload] [\r\n]
```

Where:
- **Header Byte**: Single byte indicating the start of a message
- **Message Type**: Single character indicating the message type
- **Length**: Length of the payload
- **Payload**: Message data (format depends on message type)
- **\r\n**: Carriage return and line feed characters indicating the end of the message

### Message Types

The Avl301 protocol supports three primary message types:

1. **Login Message (L)**: Used for device authentication and identification
2. **Status Message (H)**: Used for device status updates
3. **GPS/LBS Status Message ($)**: Contains position data and device status information

## Message Details

### Login Message (L)

The login message is sent by the device to identify itself to the server. It contains the device's IMEI number in a compact binary format.

#### IMEI Format

The IMEI is encoded in 8 bytes, where each byte contains two BCD (Binary Coded Decimal) digits, except for the first byte which contains only one digit in the lower 4 bits.

### Status Message (H)

A simple heartbeat message to maintain the connection and indicate the device is still active.

### GPS/LBS Status Message ($)

This message contains the device's position data and status information.

#### Payload Format

```
[Date: 3 bytes] [Time: 3 bytes] [GPS Length & Satellites: 1 byte] [Satellites Visible: 1 byte] 
[Latitude: 4 bytes] [Longitude: 4 bytes] [Speed: 1 byte] [Course & Flags: 2 bytes] 
[Cell Info: 5 bytes] [Alarm Flags: 1 byte] [Power: 1 byte] [RSSI: 1 byte]
```

#### Field Descriptions

- **Date**: Day, month, year (1 byte each)
- **Time**: Hour, minute, second (1 byte each)
- **GPS Length & Satellites**: Upper 4 bits for GPS data length, lower 4 bits for satellite count
- **Satellites Visible**: Number of visible satellites
- **Latitude**: Unsigned integer representing latitude * 600000
- **Longitude**: Unsigned integer representing longitude * 600000
- **Speed**: Vehicle speed in km/h
- **Course & Flags**: 
  - Bits 0-9: Course in degrees (0-359)
  - Bit 10: Latitude sign (0 = positive, 1 = negative)
  - Bit 11: Longitude sign (0 = positive, 1 = negative)
  - Bit 12: Position validity flag (1 = valid)
  - Bit 14-15: ACC status flags
- **Cell Info**: Cell tower information (LAC and Cell ID)
- **Alarm Flags**: Various device alarm indicators
- **Power**: Device power level
- **RSSI**: Signal strength indicator

## Traccar Implementation

The Traccar platform implements the Avl301 protocol through the following components:

### Avl301Protocol

The main protocol definition class that registers the protocol with the Traccar server and specifies connection parameters.

### Avl301ProtocolDecoder

The decoder class that processes incoming messages from Avl301 devices. Key features include:

- IMEI extraction for device identification
- Message type detection and handling
- Position data parsing and conversion
- Status flag interpretation
- Cell tower information processing for network positioning

#### Key Methods

- `readImei(ByteBuf buf)`: Extracts the device IMEI from the binary data
- `sendResponse(Channel channel, int type)`: Sends acknowledgment responses to the device
- `decode(Channel channel, SocketAddress remoteAddress, Object msg)`: Main decoding method that processes incoming messages

## Usage Guidelines

### Server Configuration

To enable the Avl301 protocol in Traccar:

1. Ensure the protocol is enabled in the `traccar.xml` configuration file
2. Configure the appropriate listening port for Avl301 devices

Example configuration:

```xml
<entry key='avl301.port'>5027</entry>
```

### Device Registration

Avl301 devices should be registered in the Traccar system with their IMEI number as the device identifier.

### Communication Flow

1. Device initiates connection to the server
2. Device sends a login message with its IMEI
3. Server acknowledges the login message
4. Device periodically sends position updates and status messages
5. Server acknowledges each message

## Troubleshooting

### Common Issues

- **Connection Problems**: Verify the device is configured with the correct server IP and port
- **Authentication Failures**: Ensure the device IMEI is correctly registered in the Traccar system
- **Position Accuracy Issues**: Check the number of satellites reported in the messages
- **Missing Data**: Verify the device is sending complete messages according to the protocol specification

### Debugging

Enable debug logging for the Avl301 protocol in the Traccar configuration:

```xml
<entry key='logger.avl301'>DEBUG</entry>
```
