# AT2000 Protocol Documentation

## Overview

The AT2000 protocol is used by Teltonika AT2000 GPS asset trackers. These devices are designed for asset tracking with long battery life (up to 17 weeks with one message per day) and include integrated magnets for easy mounting. The AT2000 is a robust standalone GPS tracker suitable for real-time tracking of various assets.

## Protocol Specifications

### General Information

- **Protocol Type**: Binary
- **Default Port**: 5027
- **Transport**: TCP
- **Encryption**: AES-128 CBC with PKCS#7 padding

### Message Structure

The AT2000 protocol uses a binary message format with the following structure:

| Field | Size (bytes) | Description |
| --- | --- | --- |
| Header | 1 | Message type identifier (0x01 for data messages) |
| Length | 1 | Length of the message excluding header and length fields |
| Data | Variable | Encrypted payload data |
| Checksum | 16 | MD5 hash for message integrity verification |

### Message Types

- **0x01**: Data message containing position and status information

### Payload Structure (After Decryption)

The decrypted payload contains the following information:

| Field | Size (bytes) | Description |
| --- | --- | --- |
| Device ID | 15 | IMEI number of the device (ASCII) |
| Timestamp | 4 | Unix timestamp (seconds since epoch) |
| Latitude | 4 | Latitude in degrees (float) |
| Longitude | 4 | Longitude in degrees (float) |
| Speed | 2 | Speed in km/h (unsigned short) |
| Course | 2 | Heading in degrees (0-359) |
| Altitude | 2 | Altitude in meters |
| Satellites | 1 | Number of satellites used for fix |
| Status | 1 | Device status flags |

## Traccar Implementation

The Traccar implementation of the AT2000 protocol consists of three main components:

### 1. At2000FrameDecoder

The `At2000FrameDecoder` extends Netty's `ByteToMessageDecoder` and is responsible for identifying and extracting complete message frames from the incoming byte stream. It performs the following functions:

- Identifies the start of a message by checking for the header byte (0x01)
- Reads the length field to determine the complete message size
- Ensures the complete message (including checksum) is available before passing it to the protocol decoder
- Handles message boundaries and buffer management

### 2. At2000Protocol

The `At2000Protocol` class extends Traccar's `BaseProtocol` and serves as the main entry point for the protocol implementation. It registers the necessary decoders and handlers in the Netty pipeline:

```java
protected void addProtocolHandlers(PipelineBuilder pipeline) {
    pipeline.addLast(new At2000FrameDecoder());
    pipeline.addLast(new At2000ProtocolDecoder(this));
}
```

### 3. At2000ProtocolDecoder

The `At2000ProtocolDecoder` extends `BaseProtocolDecoder` and is responsible for decoding the message frames into Traccar's internal position model. Key functions include:

- Decrypting the message payload using AES-128 CBC
- Extracting the device identifier (IMEI)
- Parsing position data (coordinates, speed, course, etc.)
- Creating and populating Position objects
- Handling device authentication and session management

The decoder implements AES decryption using Java's Cipher API with the following parameters:

- Algorithm: AES/CBC/PKCS7Padding
- Key: Device-specific or default key
- IV: Extracted from the message or using a default IV

## Usage Guidelines

### Configuration

To enable the AT2000 protocol in Traccar, add the following to your `traccar.xml` configuration file:

```xml
<entry key='at2000.port'>5027</entry>
```

Optional configuration parameters:

```xml
<entry key='at2000.timeout'>60</entry> <!-- Connection timeout in seconds -->
```

### Device Setup

To configure an AT2000 device to communicate with Traccar:

1. Set the server IP address and port (5027) on the device
2. Ensure the device is configured to use TCP communication
3. Configure the reporting interval as needed
4. Register the device in Traccar using its IMEI number

### Troubleshooting

Common issues and solutions:

1. **Connection problems**: Verify firewall settings allow traffic on port 5027
2. **Authentication failures**: Ensure the device IMEI is correctly registered in Traccar
3. **Decryption errors**: Check if the device uses a custom encryption key
4. **No position updates**: Verify the device has a valid GPS fix and is properly configured
